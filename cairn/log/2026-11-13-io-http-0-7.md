# io-http 0.7, the frame bound handed to its parser

io-jmap moved from io-http 0.6 to 0.7.0, published the same day; `cargo tree -i io-http` shows one version. **Breaking**: io-http's types are in the public API, and its send and read errors, carried by the `Send`, `ReadHeaders` and `ReadChunks` variants, gained variants.

Two places stopped building, both in rfc8620/event_source/subscribe.rs, the one coroutine that serialises its request and drives the SSE parser itself. `to_http_11_vec` returns a `Result`: `JmapEventSource::new` returns the new `InvalidRequest(HttpRequestError)`, so an `Authorization` value holding a CR LF is refused where io-http 0.6 wrote it as a second header line. `InvalidLastEventId` stays and is checked first. The four other request coroutines go through `Http11Send`, which fails its first resume with `InvalidRequest`, already under their `Send` variant. **Breaking**: the new variant.

The private `FrameLen` is gone, as the entry bounded-frames-and-checked-inputs announced: `max_frame_len` is handed to `SseFrameParser` as `max_line_len` and `max_event_len` when the stream starts, and `LineTooLarge` and `EventTooLarge` both read as `FrameTooLarge`. The defaults do not move: 64 KiB a frame, 1 MiB a chunk. Handing both over is not optional: left at the parser's defaults, a `max_frame_len` raised past 64 KiB would have been capped by them.

The two counts differ. `FrameLen` counted the raw bytes of every field line since the last blank line, names included; the parser bounds each line, then the data of the frame as the caller reads it, the values of the `data` lines joined by a LF. Names (`data: ` is 6 bytes a line) and the `event`, `id`, `retry` and unknown lines no longer add up; they are bounded as lines, and replaced or dropped, never kept, so what the parser holds stays bounded. The new count is never above the old one: no stream accepted before is refused now. The frames ahead of an oversized one in the same chunk are now yielded before the failure. `max_frame_len` was never released with the old count.

One test moved with the count: `data_lines_without_blank_line_return_frame_too_large` sent four lines of 16 raw bytes then `data: 0`, 71 raw bytes against a limit of 64, which is 45 bytes of data and passes (`expected FrameTooLarge, got Yielded(WantsRead)`). It now sends the four lines, a fifth bringing the data to 64 bytes, which must pass, then an empty `data:` line, 65 with its LF, which must fail. The other event source tests pass untouched, `line_that_never_ends_returns_frame_too_large` and `frames_and_comments_within_limit_keep_streaming` among them. New: `authorization_with_cr_lf_returns_invalid_request`.

The `Host` header was checked: io-http 0.7 writes it from the URL, port included when it is not the default, and the five `request_host_keeps_the_port` tests pass untouched.

The requests spec no longer says a query token reaches the trace log through io-http: 0.7 logs a request with the userinfo and the query values of its URL redacted. Checked by widening the capture of tests/logs.rs to io-http's records for one run, which held neither `hunter2` nor `s3cr3t`; the test itself is unchanged.

Capabilities moved: responses ("Event source frames are bounded" modified), requests ("Secrets stay out of Debug and logs" modified, new: "A header value cannot split a request head").
